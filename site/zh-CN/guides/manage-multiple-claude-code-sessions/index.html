Claude Code 指南

如何在 macOS 管理多个 Claude Code 会话

隔离代码、分清任务所有权，再把注意力信号集中起来。这样才是有效并行，而不是让几个 Agent 同时盲目修改同一个问题。

发布于 2026-10-08 · 阅读约 7 分钟

推荐配置：每个 Claude Code 会话使用独立 Git worktree、单一明确任务和可识别标题。需要进程跨断线存活时使用 tmux；主要问题是判断哪个会话需要你时，使用理解 Agent 状态的终端。

1. 给每个会话独立工作目录

两个 Agent 修改同一个 checkout，可能互相覆盖文件、让对方的假设失效，并产生混杂的 Git diff。Git worktree 能提供独立目录，同时共享仓库对象。

git worktree add ../project-auth -b agent/auth
git worktree add ../project-tests -b agent/tests

cd ../project-auth
claude

在另一个 worktree 启动第二个会话。让每个分支足够聚焦，可以独立 review 和合并。

2. 分配结果，而不是重叠活动

“改进后端”不是一个好的并行任务。“给接口 X 增加参数校验”和“给问题 Y 增加回归测试”才有明确所有权。启动会话前应说明：

  • 预期结果；
  • 允许负责的文件或子系统；
  • 不得修改的边界；
  • 证明完成的测试命令。

如果两个任务必须修改同一个核心文件，应串行处理，或让一个 Agent 负责实现，另一个只做研究与 review。

3. 让会话容易识别

六个会话都叫“zsh”时，标签标题没有帮助。会话标识应包含项目、任务和分支。gilvt 的会话行显示工作目录、分支与当前动作，也允许在不改变 Agent session 的情况下重命名。

4. 集中注意力，而不是轮询标签页

并行 Agent 最昂贵的部分，是反复确认每个会话是否还在执行。Claude Code hooks 与会话记录可以区分活动、审批、问题、错误和完成。

gilvt 把需要用户的会话排在左栏顶部。⇧⌘J 可以跨标签页和窗口跳到下一个等待会话；系统通知则覆盖你在编辑器或浏览器中的时间。

5. 下一条指令之前先 review 当前轮次

并行输出积累很快。应按任务和轮次 review，而不是等所有分支都变得很大。检查执行过的命令、修改文件、相关 diff 和验证结果。接受当前工作后先提交或建立 checkpoint，再给出方向明显不同的新任务。

6. 明确选择持久化方式

Claude Code 能恢复持久会话，tmux 能保留同一个运行进程，两者并不相同：

  • Claude resume 从保存的 session 重建 Agent 对话。
  • tmux attach 在 server 仍存活时重新连接同一个 shell 和进程。
  • gilvt restore 重建本地窗口布局，并提供受支持的 Agent 会话恢复入口。

远程机器或必须跨 GUI 退出存活的进程适合 tmux；持久对话历史适合 Agent resume；两者可以组合。

7. 限制并发数量

会话更多不一定更快。先从两到三个独立任务开始。只有在 review 延迟仍然较低，而且任务不争用相同文件、测试环境或心智模型时，再增加并发。

在 gilvt 中：按 ⇧⌘N 在目录或新 worktree 中创建 Claude Code 会话，再通过左栏和 Session Center 导航、review 和恢复。
