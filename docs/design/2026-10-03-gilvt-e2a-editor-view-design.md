# gilvt E2a：内置编辑器视图（设计）

日期：2026-10-03
状态：已实现（2026-10-04，GUI 验收 S0 + V1–V4 通过）。与最初设计不同的地方见文末「实现与设计的差异」，正文已改成实现后的样子
依赖：[E1 编辑核心](2026-10-03-gilvt-e1-editor-core-design.md)（已合入 master）、[E2 笔记](2026-10-03-gilvt-e2-editor-view-notes.md)

## 1. 目标与范围

在 gilvt 里提供一个**内置的通用文本编辑器**，替代现在「跳到 VS Code / 系统文本编辑器」的做法。编辑区是一种新的 pane（`PaneView::Editor`），建立在 `gilvt-editor` 之上。

E2 拆成两步，本文只管 **E2a（能用）**：

| | E2a（本文） | E2b（之后） |
|---|---|---|
| 打开与布局 | 分屏 / 新标签 / 聚焦已有；⌥ 翻转 | — |
| 编辑 | 输入、输入法、选区、鼠标、撤销重做、自动换行、缩进、滚动、剪贴板 | 查找替换（E3） |
| 保存 | ⌘S、头部按钮、`ModifiedOnDisk` 的简版确认条 | 外部修改横幅（重新载入 / 对比）、主动检测 |
| 关闭与退出 | 关 pane / 标签 / 窗口 / ⌘Q 的未保存保护 | — |
| 被拒绝的文件 | 红色横幅 + 外部编辑器 / 预览 | 指定编码或只读重新打开 |
| 状态栏 | 行列、选区字符数、语言名、编码、换行符、行数 | 混合换行符提示 |
| 入口 | 配置弹窗 / 展开行 / 预览里的「编辑」、`⌘O`、`⌘⇧`+点击 | `gilvt edit <文件>` |
| 其他 | DebugState、GUI 验收 | 语法高亮 |

不做（也不在 E2b）：插件、LSP、代码折叠、多光标（E3 评估）、编辑 pane 的重启恢复。

## 2. 用户故事

照这个顺序走一遍（交互原型已在评审中确认）：

1. 用户在右侧「配置」标签点 Skills 的「查看 ›」，弹窗列出 Skills。
2. 点一行是**预览**（和现在一样，Quick Look，←/→ 切换）；鼠标悬停时行尾出现「编辑」按钮，预览里按 `E` 也是编辑。
3. 点「编辑」：在当前终端 pane 的**右边**出现编辑 pane；标签太满时改为**新开标签**（见 §4）。⌥+点「编辑」（预览里 ⌥E）翻转默认选择。
4. 在编辑 pane 里输入。有未保存修改时头部和所在标签显示 ●。长行自动换行，续行的行号栏留空。
5. ⌘S 或头部「保存 ⌘S」保存；● 消失。
6. 同一个文件已经在编辑 pane 里时再点「编辑」，聚焦那个 pane（在别的标签就切过去并闪一下），不重复打开。
7. 关闭有未保存内容的 pane / 标签 / 窗口 / ⌘Q：弹确认条，不会静默丢内容。
8. 被拒绝的文件（二进制、超过 64 MB、旧编码无法原样保存、超长行）：不开 pane，显示红色横幅，说明原因。
9. 保存时磁盘上的文件被外部改过：简版确认条「仍然覆盖 / 取消」，绝不静默覆盖。

## 3. 界面

沿用 E2 笔记中已确认的样式，E2a 实现的部分：

- **头部**（26px 高）：文件名 + 未保存圆点 + 路径（过长从左边截断，保留文件名所在的目录尾部）+ 「保存 ⌘S」「✕」。只读时在文件名后显示「只读」。
- **正文**：左侧行号栏；**自动换行**，只在逻辑行的第一段标行号；当前行底色横跨它的全部显示行；列表项（`-`、`*`、`1.`）续行与首行文字左对齐，其他行续行与该行缩进对齐。选区可以跨过换行点。
- **状态栏**（22px 高）：`第 N 行，第 M 列 · 已选 K 字符` ｜ 语言名 ｜ 编码 ｜ 换行符 ｜ `L 行`。
- **横条**（头部下方，同一时刻只显示一条，优先级自上而下）：
  1. 关闭确认条：`要保存对 X 的修改吗？` 取消 / 不保存 / 保存 ⏎
  2. 外部修改确认条：`文件已在磁盘上被修改。` 取消 / 仍然覆盖
  3. 保存失败条（红）：原因 + 必要的动作（`Unrepresentable` 提供「跳到出错位置」）
- **窗口级未保存确认条**（关窗口 / ⌘Q 时，见 §6）和**窗口级红色横幅**（打开被拒绝时）：`不能编辑 X：<原因>` + 「在外部编辑器中打开」「预览」「知道了」。

窗口太窄（正文不足 10 列）时只显示头部和一句「窗口太窄」。

## 4. 打开路由

入口统一调用 `Workspace::open_editor(path, line: Option<u32>, origin: Option<PaneId>, flip: bool)`：

1. **文件已在某个编辑 pane 里**（整个窗口内按规范化路径判断）：切到那个标签，聚焦该 pane，闪烁高亮；若给了 `line` 就跳到该行。不重复打开。
2. 否则调用 `Buffer::open`：被拒绝 → 红色横幅，结束（不新建 pane，不新建标签）。
3. 否则决定放哪里（纯函数 `route(tab_pane_count, target_cols, flip) -> Split | NewTab`）：
   - 默认：当前标签已有 `≥ 3` 个 pane，或者在 `origin`（缺省为聚焦 pane）右边分屏后任何一边 `< 60` 列 → **新标签**；否则 **分屏**（`Axis::Row`，插在 origin 右边，复用 `split_target`）。
   - `flip` 为真时取相反结果。**强制分屏时即使小于 60 列也照做**。
   - 阈值是两个常量：`MAX_PANES_BEFORE_TAB = 3`、`MIN_SPLIT_COLS = 60`。`target_cols` 估算的是**目标 pane 实际排版出来的宽度**（不是标签宽度除以 pane 数），用终端单元格宽度换算；目标 pane 第一帧之前宽度为 0，此时默认开新标签（`flip` 为真则分屏，强制分屏照做）。
4. **新标签**：插在当前标签的**右边**；标题是文件名，有未保存修改时带 ●；记录 `origin_tab`，关掉这个标签后回到它。
5. 键盘焦点：分屏时留在原 pane（和固定预览一致）；新标签时进入编辑 pane。

`⌘O` 和 `⌘⇧`+点击路径改成走这条路由；旧的 `open_in_editor` 保留给 `⌘⌥O`（预览里或编辑 pane 里）和被拒绝文件横幅里的「在外部编辑器中打开」。头部右键菜单不在 E2a（留给 E2b）。

## 5. 架构

方案 A：**网格排版 + 自定义 Element**。编辑 pane 使用终端的等宽字体与单元格尺寸；换行按显示列数计算（CJK 占 2 列，即 E1 的 `display_col`），换行结果是纯数据，不依赖 gpui；绘制时才对可视范围内的显示行 `shape_line`，与 `terminal_element.rs` 同一写法，输入法沿用 `ElementInputHandler`。

不选 `shape_text` 的 `WrappedLine`（换行逻辑无法脱离 gpui 测试，光标/点击要反查排版）和逐行 div + `uniform_list`（换行后行高不一）。

```
gilvt-app/src/editor/
  wrap.rs     WrapMap：逻辑行 ↔ 显示行；列表项续行缩进；按 Change 增量更新      （纯逻辑）
  indent.rs   缩进单位检测、回车沿用缩进、Tab/⇧Tab 整块缩进                      （纯逻辑）
  model.rs    EditorModel：Buffer + WrapMap + 滚动 + 选区；全部键鼠命令           （纯逻辑）
  view.rs     EditorView（gpui Entity）：焦点、键盘、鼠标、输入法、滚动事件
  element.rs  EditorElement：行号栏、文本、选区、光标、预编辑下划线
  chrome.rs   头部、横条、状态栏
workspace/editor.rs   PaneView::Editor 接线：路由、聚焦已有、关闭与退出保护、DebugState
```

### 5.1 WrapMap

- 输入：每个逻辑行的文本、宽度（列数）、制表符宽度。输出：每个逻辑行对应的显示行区间 `[(start_col, end_col)]` 与续行缩进。
- 换行点优先在空白之后；没有空白（长 URL、CJK 连续文字）时在宽度处断，**不切断字素簇**（组合字符、emoji ZWJ 序列）、不把 2 列宽字符拆开（行尾剩 1 列放不下时整个挪到下一行）。
- 增量：`apply(Change)` 只重算 `Change` 覆盖的逻辑行，其余行下标整体平移；宽度变化时整体重算，并让调用方按「光标所在字符」重新定位滚动。
- 提供：`display_row_of(Position)`、`position_at(display_row, visual_col)`、`rows_for_line(line)`、`total_rows()`。

### 5.2 EditorModel

- 持有 `Buffer`、`WrapMap`、`scroll_row`（显示行）、`preferred_col`（↑/↓ 保持的视觉列）、鼠标拖动状态。
- 命令（均经 `Buffer` 的单一 `replace` 入口，因而可撤销）：输入、回车（沿用缩进）、Tab / ⇧Tab、退格、删除、按词删除、剪切 / 复制 / 粘贴、全选、撤销 / 重做；移动：← → ↑ ↓、⌥← →（词）、⌘← →（行首尾）、⌘↑ ↓（文首尾）、Home / End、PgUp / PgDn，所有移动配合 ⇧ 扩选（例外：`⌘⇧↑` / `⌘⇧↓` 在编辑 pane 里仍是全局的上一个 / 下一个会话，见 §5.5，所以「扩选到文首 / 文尾」没有对应快捷键）。
- **↑/↓** 按显示行移动并保持视觉列；**Home/End** 第一次到当前显示行首尾，再按到逻辑行首尾；**点击**落在最近字符，双击选词（`word_range_at`），三击选逻辑行，点行号栏选整个逻辑行。
- 只读（`ReadOnly` 或含超长行）时拒绝一切修改，仍可移动、选区、复制。
- 滚动：跟随光标；鼠标滚轮、触控板像素滚动；窗口宽度变化后光标所在字符保持在屏幕同一位置。

### 5.3 indent.rs

- 缩进单位：文件里已有以 Tab 缩进的行 → Tab；否则空格，Markdown / YAML / JSON 为 2 个，其他 4 个；文件名是 `Makefile` / `makefile` / `GNUmakefile` 一律 Tab。
- 回车：新行沿用上一行的前导空白；上一行是列表项（`- `、`* `、`1. `）时额外带出相同的列表前缀（空列表项再回车则去掉前缀，同常见编辑器）。
- Tab：无选区插入一个缩进单位；选区跨多行时给每个被选行加一级。⇧Tab：减一级（不足一级则去掉现有的）。
- 整块缩进是一次撤销。

### 5.4 view / element / chrome

- 键盘：普通字符与输入法走 `EntityInputHandler`（`replace_text_in_range` / `replace_and_mark_text_in_range` / `bounds_for_range`），预编辑期间显示下划线，不触发保存与撤销合并；快捷键走 gpui action。
- 绘制只处理可视范围内的显示行，逐行 `shape_line`；选区、当前行底色、光标（静态实心竖条，不闪烁）、行号栏（续行留空）。
- 字体与字号使用终端设置（`Settings`），改设置时重排。
- 头部、横条、状态栏只是普通元素，不进入文本区的重绘。

### 5.5 快捷键

| 键 | 行为 |
|---|---|
| ⌘S | 保存（`save()`） |
| ⌘Z / ⇧⌘Z | 撤销 / 重做 |
| ⌘C / ⌘X / ⌘V / ⌘A | 复制 / 剪切 / 粘贴 / 全选 |
| ⌘W | 关闭当前编辑 pane（有未保存内容则出确认条） |
| Tab / ⇧Tab | 缩进 / 反缩进（多行选区整块） |
| ⌥⌫ | 按词删除 |
| Home / End | 先到当前显示行首 / 尾，再按到逻辑行首 / 尾 |
| Esc | 没有横条时发出 `Leave`（让出焦点，同预览 pane）；有横条时按横条规则处理 |
| ⌘O、`⌘⇧`+点击 | 内置编辑（原来是外部编辑器） |
| ⌘⌥O | 在外部编辑器中打开磁盘上的文件（不保存；编辑 pane 里把光标所在行传给外部编辑器，缓冲区有未保存修改时该行可能与磁盘文件不一致） |
| Esc（预览中） | 关闭预览 |

终端 pane 的快捷键（⌘D 分屏、⌘T 新标签、⌘1–9、⌘Q、⌘⇧↑ / ⌘⇧↓ 等）在编辑 pane 里保持一致，不被编辑键覆盖；这些命令不与上表冲突。

## 6. 错误与边界

**打开时**

| 情况 | 行为 |
|---|---|
| 正常 | 可编辑 pane |
| `ReadOnly`（无写权限） | 只读打开，头部显示「只读」，输入和 ⌘S 无效，可选择、复制、滚动 |
| `Binary` / `TooLarge`（64 MB）/ `UnsupportedEncoding` / `NotAFile` | 不开 pane；红色横幅 + 「在外部编辑器中打开」（二进制、超大不提供）+ 「预览」 |
| 文件不存在 | 提示「文件不存在」，不新建 |
| 任一行超过 20 万字符 | **只读**打开并提示「含超长行，暂不支持编辑」（E1 已知这类行每次按键约 50 ms，E4 解决）。`sync()` 在每次修改后会重新检查被改动的行，所以粘贴出超长行同样变成只读 |

**保存时**

- 成功：清除 ●，更新所在标签。
- `ModifiedOnDisk`：外部修改确认条，「仍然覆盖」调 `save_overwrite()`，「取消」保留缓冲区。⌘S、头部按钮、关闭确认条的「保存」、⌘Q 的「全部保存」遇到都走同一个确认条，不静默覆盖。
- `PermissionDenied`、`Io`：红色保存失败条，写明原因，缓冲区保持脏。
- `Unrepresentable{line, col}`（旧编码写不进的字符；`col` 是字符数不是字素）：保存失败条 + 「跳到出错位置」（位置 = 该行起始字符偏移 + `col`）。
- 保存失败时，关闭 / 退出流程中止，停在对应的确认条。

**关闭与退出保护**

- 关 pane（✕、⌘W）、关标签：在该 pane 内弹确认条（取消 / 不保存 / 保存 ⏎，默认保存）。关窗口、⌘Q：窗口级确认条列出所有未保存文件名，按钮 取消 / 不保存并关闭 / 全部保存并关闭；**含未保存文件时 ↩ = 全部保存并关闭，Esc = 取消，⌘↩ = 不保存并关闭**。只有 Agent 会话的确认条保持原样（↩ = 取消）。
- ⌘Q 跨窗口检查时，任何一个窗口读不出状态就中止退出，不会把读不出的窗口当作已保存。
- 「保存后关闭」是否生效记在横条状态里（`Bar::Modified { closing }`）：保存遇到 `ModifiedOnDisk` 时横条记住这是关闭流程，「仍然覆盖」成功后才关闭 pane。
- 标签上的 ● 在该标签里**任一**编辑 pane 有未保存修改时显示（不只看聚焦的那个）。
- 本地没有未保存内容时行为与现在完全一致，不增加任何确认。

**其他**

- 外部程序（比如 Agent）在编辑期间改了文件：E2a 不主动检测，保存时才会遇到 `ModifiedOnDisk`（主动检测在 E2b）。
- 粘贴很大的文本：一次 `replace`，一次撤销；不做逐字合并。
- 编辑 pane 不进入布局快照：重启后丢弃，与固定预览 pane 一致（`persist/snapshot.rs` 里同样处理，树随之收拢）。

## 7. DebugState

`windows[i].editors[]`（GUI 验收用；字段在每个窗口下，不在 `DebugState` 根上，GUI 用例读 `windows[0].editors[0].…`）：

```
{ "pane": <id>, "tab": <index>, "path": "...", "dirty": bool, "readonly": bool,
  "cursor": {"line": n, "col": n}, "selection_chars": n, "scroll_row": n,
  "wrap_cols": n, "rows": n, "bar": "none|close|modified|save_error",
  "rect": [x,y,w,h], "save_rect": [x,y,w,h], "close_rect": [x,y,w,h] }
```

rect 是 `[x, y, w, h]` 数组，没画出来时为 `null`。配置弹窗每行的「编辑」按钮矩形在 `inspector.config.dialog.rows[].edit_rect`（RectId `ConfigDialogEdit`）：该行画出来就有值，**按钮被 hover 隐藏时也记录**，但隐藏的按钮不响应点击，所以 GUI 用例要先 hover 该行再点。`wrap_cols` / `rows` 是最后一次绘制时的值。`docs/debug-state.md` 同步。

## 8. 测试与验收

**自动化（`cargo test`）**

- `wrap.rs`：基本换行、CJK 不拆开、emoji / 组合字符不被切断、无空白长串、列表项续行缩进、宽度变化后光标字符不变、「增量更新 = 整体重算」随机差分。
- `indent.rs`：Tab / 2 / 4 空格检测、Makefile、回车沿用缩进与列表前缀、整块缩进 / 反缩进、一次撤销回到原状。
- `model.rs`：↑/↓ 在换行点保持视觉列、Home/End 两段式、选区跨续行、滚动跟随光标、只读拒绝所有修改。
- `route`：纯函数表驱动测试（pane 数 × 列数 × flip）。
- workspace：同文件聚焦已有 pane、关闭后回到来源标签、未保存列表、`persist` 丢弃编辑 pane。

**GUI 验收**（`tests/gui/cases/`，新用例 `V1`–`V4`（section V），沿用 sandbox + drive）

- `V1`：配置弹窗点「编辑」→ 右侧出现编辑 pane → 输入 → ⌘S → 磁盘文件内容正确；预览里按 E 同效。
- `V2`：窄窗口或 ≥3 pane 新开标签；⌥ 翻转；同文件再点聚焦已有 pane；关闭文件标签回到来源标签。
- `V3`：未保存时关闭 → 确认条；「不保存」后磁盘不变；外部改文件后 ⌘S → 「仍然覆盖 / 取消」；⌘Q 列出未保存文件。
- `V4`：中文输入法预编辑、点击落点、拖动选区、长 description 换行（截图对照）、被拒绝文件的红色横幅。

前台点击需要解锁屏幕和用户同意（沿用 `tests/gui` 的约定）。

## 10. 风险

- **CJK 回退字体宽度**与 2 个单元格可能有细微偏差（终端有同样限制，接受）。
- **输入法**：预编辑下划线与候选窗定位靠 `bounds_for_range`，只能真机验证，列在 GUI 验收 `V4`（实际无法自动化，见文末差异）。
- **文件很大时的换行成本**：WrapMap 首次构建是 O(文件长度)；64 MB 文件上限下需要在后台分块构建，E2a 先同步构建，**没有**做「正在排版」占位，若 E4 实测过慢再处理。

## 11. 实现与设计的差异

以下是实际实现与最初设计不同的地方（正文已改成实现后的样子），每条一行原因：

- **光标是静态实心竖条，不闪烁**：终端同样不闪烁，闪烁留待后续。
- **头部右键菜单「在外部编辑器中打开」不在 E2a**：只保留 `⌘⌥O` 和被拒绝文件横幅里的按钮；菜单留给 E2b。
- **`EditorView::open` 改为 `load_model(path)` + `EditorView::new(model, cx)`**：`cx.new(|cx| …)` 的闭包必须返回 `Self`，不能返回 `Result`；所以先 `load_model`（拒绝则只出横幅，不建 entity）再 `new`。
- **对 E1 的唯一改动是导出 `cell_width`**（§9）。
- **打开路由用目标 pane 实际排版宽度估算列数**，不是「标签宽度 ÷ pane 数」：上下分屏时更准；第一帧之前宽度为 0 ⇒ 默认新标签（`flip` 则分屏，flip 仍强制分屏）。
- **GUI 用例编号是 `V1`–`V4`（section V），不是 `E1`–`E4`**：`E` 已被旧的 Markdown / Mermaid 验收段占用。
- **DebugState**：`editors[]` 在每个窗口下（`windows[i].editors[]`）而非根；rect 键是 `save_rect` / `close_rect`，值是 `[x,y,w,h]` 数组（不是对象）；配置弹窗的按钮矩形是 `inspector.config.dialog.rows[].edit_rect`（RectId `ConfigDialogEdit`，原设计叫 `EditBtn`），按钮 hover 隐藏时也记录矩形，GUI 用例要先 hover 再点（gpui 会预绘隐藏元素）。
- **`⌘⇧↑` / `⌘⇧↓` 仍是全局会话导航**：§5.5 要求终端 pane 的快捷键在编辑 pane 里保持不变，优先于 §5.2 的「⇧ 扩选每个移动」。**已知缺口**：不能用键盘一步扩选到文首 / 文尾（`⌘⇧←/→`、`⇧PgUp/PgDn`、`⇧`+点击、`⌘A` 可用）；日后可加 `EDITOR_CONTEXT` 绑定。
- **窗口级未保存文件确认条的默认是「全部保存并关闭」**（↩；Esc = 取消，⌘↩ = 不保存并关闭），原计划写的是 ↩ = 取消，与 §6「默认保存」冲突，以 spec 为准；只含 Agent 会话的确认条不变（↩ = 取消）。
- **⌘Q 跨窗口时，任何窗口读不出状态就中止退出**：不能把读不出的窗口当作已保存（否则静默丢数据）。
- **「关闭后保存」标志放在 `Bar::Modified { closing }`**：避免标志过期后，之后无关的覆盖保存意外关掉 pane。
- **标签 ● 在标签内任一编辑 pane 脏时就显示**，不只看聚焦的 pane（分屏标签里否则会藏住未保存状态）。
- **编辑 pane 里的 `⌘⌥O` 打开的是磁盘上的文件，不保存**；缓冲区有未保存修改时传给外部编辑器的行号可能不准。
- **没有实现「> 5 MB 显示『正在排版』占位」**：排版是同步的；若 E4 实测大文件打开明显卡顿再做。
- **`sync()` 会对改动的行重新检查 20 万字符超长行的只读规则**（不只在整体重排时检查）：否则粘贴出超长行后仍可编辑。
- **缩放窗口后保持视口的第一行不动，不是光标所在字符**（§5.1 / §5.2 原写光标字符屏幕位置不变；`set_viewport`）：只在缩放前光标可见时才把光标重新带回视口——原本在屏幕外的光标不能拖动滚动位置。
- **没有横条时 Esc 发出 `Leave`**（让出焦点，与预览 pane 一致），设计里没有写。

### 已接受的自动化缺口

DebugState / GUI 自动化覆盖不到的地方（用截图判定、按键或人工确认）：编辑 pane 内行内横条的按钮没有 rect（「不保存」靠标签关闭条的 ⌘↩ 间接覆盖，「仍然覆盖」之后磁盘内容无法用键盘验证）；被拒绝文件的横幅和换行布局（行数 / 行号栏）不在 DebugState 里；输入法预编辑没有自动化（编辑 pane 不导出 marked text，`type "你好"` 只验证了直接插入）；终端列数 / 字号没有导出，60 列规则只能从「分屏还是新标签」间接看到。
