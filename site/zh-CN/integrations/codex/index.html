带实时状态与逐轮 review 的 Codex CLI

Codex 继续运行在原生 TUI 中。gilvt 组合本地 hooks、rollout 记录和进程身份，显示会话正在执行、等待、失败或完成。

更新于 2026-10-08 · gilvt {{VERSION}}

设置：安装 gilvt，打开 pane 并运行 codex。受支持的 hooks 会传给启动进程，不会永久替换你的 Codex 配置。

统一的 Codex 活动状态

gilvt 读取受支持的 Codex hook 事件和本地 rollout 数据，再与持有进程的 pane 关联。左栏能够区分执行、审批或用户输入等待、错误、完成轮次和子 Agent 活动。

  • ⇧⌘J 跳到下一个需要注意的会话。
  • 时间线显示命令、编辑、TODO、失败和子 Agent 生命周期。
  • 产物汇总修改文件并打开本轮 diff。
  • 监控官跨窗口汇总 Codex、Claude Code 和普通终端。

不暴露秘密的配置摘要

「配置」检查器读取有效 Codex 模型、权限、MCP 名称、hooks、skills 和 AGENTS.md 来源。命令、URL、token 和环境变量值会被主动省略。

恢复与其他命令名

Session Center 索引持久 Codex session，并在原项目中恢复受支持的记录。团队如果通过其他命令包装 Codex，可以在 gilvt 的 [agent] 配置中加入命令名；精确能力仍取决于 wrapper 是否保留相关进程和 session 信号。

兼容性降级

Agent CLI 格式会持续变化。gilvt 为支持的格式保留 fixture 和 fake-agent 剧本。hook 不可用时，pane 仍然正常工作，会话会标记为推断或精简，而不会获得不安全的精确控制。
