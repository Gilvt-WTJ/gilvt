# I18 没有 shell 集成时新标签延迟输入
requires: sandbox
checklist: I18
scenarios: [default]

`shell_integration = false` 后重启 gilvt：新标签没有提示符上报，gilvt 固定等 800 ms 再输入命令，字符不丢。结束时恢复配置。

## steps
```gilvt-steps
restart --set shell_integration=false
wait   windows[0].tabs[0].panes[0].foreground == "shell" && windows[0].tabs[0].panes[0].screen_tail[*] contains "sandbox$" timeout=15s
type   "mkdir -p ~/work/i18 && cd -P ~/work/i18 && claude @scenario:default i18 占住当前 pane\n"
wait   windows[0].tabs[0].panes[0].foreground == "agent:claude" timeout=15s
key    cmd+shift+n
wait   windows[0].overlay.kind == "new_agent" && windows[0].overlay.preview.head == "将在新标签执行：" timeout=5s
type   "i18 新标签里的完整任务"
key    enter
wait   windows[0].tabs[*] exists count=2 && windows[0].tabs[1].panes[0].foreground == "agent:claude" timeout=15s
assert windows[0].tabs[1].panes[0].screen_tail[*] contains "&& claude 'i18 新标签里的完整任务'"
wait   windows[0].tabs[1].panes[0].screen_tail[*] contains "⏺ OK: i18 新标签里的完整任务" timeout=15s
# 没有 hook（没有 shell 集成就没有包装函数）：两个标签各是一个精简模式会话，约 3 秒后出现在左栏。
# 它们绑定的是已经写过提示词的会话记录，名字是「新会话」，直到下一条提示词（清单「已知限制」），所以不按名字找
wait   windows[0].tabs[0].panes[0].session != null && windows[0].tabs[1].panes[0].session != null && windows[0].sidebar.rows[?lite==true] exists count=2 timeout=15s
shot   i18
restart --set shell_integration=true
```

## judge
- 新标签里的命令完整（断言：命令行与 fake claude 收到的提示词都是完整的「i18 新标签里的完整任务」）。
- 两个标签各绑定一个精简模式会话（断言：两个 pane 都有会话、左栏两行 `lite`）；它们的名字是「新会话」，这是清单「已知限制」
  里写明的行为（精简模式绑定到已有会话记录时名称为「新会话」，直到下一条提示词），不是失败。
- `i18`：命令出现在提示符之后（慢机器上可能先于提示符出现，已知限制；仍然执行即可）。
- 最后的 `restart` 把配置改回 `shell_integration = true`；它失败时后面的用例都不可信，先停下来报告。
