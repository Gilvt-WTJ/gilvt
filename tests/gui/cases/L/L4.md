# L4 失败的 turn 排在正常完成之前
requires: sandbox
checklist: L4
scenarios: [hist-claude, api-error]

先写入一个正常完成的会话，再写入一个以 API 错误结束的会话（时间更晚）。智能排序按 需要你 → 失败 → 已完成 分档，失败的排在前面，
即使它完成得更晚；失败的 turn 在 Review 里显示为失败。

## steps
```gilvt-steps
wait   windows[0].tabs[0].panes[0].foreground == "shell" && windows[0].tabs[0].panes[0].screen_tail[*] contains "sandbox$" timeout=15s
sh     'rm -rf "$HOME/.claude/projects" "$HOME/.codex/sessions"'
type   "mkdir -p ~/work/l4 && cd -P ~/work/l4 && clear\n"
wait   windows[0].tabs[0].panes[0].cwd contains "/work/l4"
seed   hist-claude --cwd work/l4 --id c1a0de00-0000-4000-8000-0000000b0401 --prompt "l4 正常完成"
seed   api-error --cwd work/l4 --id c1a0de00-0000-4000-8000-0000000b0402 --prompt "l4 失败了"
key    cmd+shift+r
wait   windows[0].overlay.kind == "sessions" timeout=15s
key    cmd+2
wait   windows[0].overlay.kind == "session_center" && windows[0].overlay.tab == "review" && windows[0].overlay.rows[1] exists && windows[0].overlay.rows[2] !exists timeout=15s
assert windows[0].overlay.rows[0].session_key contains "0b0402" && windows[0].overlay.rows[0].priority == "failed"
assert windows[0].overlay.rows[1].session_key contains "0b0401" && windows[0].overlay.rows[1].priority == "completed"
shot   l4-order
key    space
wait   windows[0].overlay.session_review.session_key contains "0b0402" && windows[0].overlay.session_review.loading == false && windows[0].overlay.session_review.turns[0] exists timeout=10s
assert windows[0].overlay.session_review.turns[0].outcome == "failed" && windows[0].overlay.session_review.turns[1] !exists
shot   l4-failed
key    esc
key    esc
wait   windows[0].overlay == null
```

## judge
- `l4-order`：失败的会话在第一行，状态是红色的「失败」；正常完成的会话在它下面。
- `l4-failed`：Review 里这一轮的结果是红色的「失败：…」，没有崩溃或空白。
