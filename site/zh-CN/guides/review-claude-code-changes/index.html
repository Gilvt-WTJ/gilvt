如何 review Claude Code 和 Codex 改了什么

代码由 Agent 来写，你的工作就变成了读代码。大多数人为此要切到 IDE 看一眼再切回来。这篇讲怎么在终端里按轮次 review Agent 的改动：用 git、用 Agent 自带的命令，以及用 gilvt。

发布于 2026-10-19 · 阅读约 7 分钟

简单说：每轮结束就 review，不要等到最后；每个任务从干净或已提交的工作区开始，这样 diff 里只有 Agent 的改动；当前状态用 Claude Code 或 Codex 的 /diff 看，历史用 git 看。同时跑好几个会话，或者会话结束后还想回看某一轮时，就需要有人替你保存每一轮的快照。

按轮次 review，而不是等整个分支做完

Agent 一轮可能改十几个文件，下一轮又在这些改动上继续。如果只看最终的 diff，第二轮的一个错误假设会被后面所有改动埋住。趁每一轮还小的时候读，速度更快，也能在 Agent 沿着错误继续之前把它拉回来。

每一轮看四件事：执行了哪些命令（有没有失败）、改了哪些文件、diff 本身，以及它声称的验证结果，比如测试有没有真的跑过。

用 git

git 适用于任何 Agent。每个任务从已提交的工作区开始，工作区的 diff 就只包含 Agent 的改动：

git status --short          # 改了什么，包括新文件
git diff --stat             # 每个文件改动的大小
git diff                    # 已跟踪文件的改动
git diff --word-diff        # 按词显示改动，适合文档和配置
git add -p                  # 逐块接受这一轮的改动

有两个习惯很关键：每轮结束后把接受的部分提交（或暂存），下一次 git diff 就只剩新一轮的改动；另外，git diff 不显示还没被跟踪的新文件，新文件要在 git status 里看。

用 Agent 自带的命令

Claude CodeCodex CLI
看改动/diff：工作区的改动，包括 Claude 到目前为止的编辑/diff：git diff，包括还没被跟踪的文件
让它自查/review（/code-review 的别名）/review，或 codex review --uncommitted
撤销一轮Esc Esc 或 /rewind：把代码、对话或两者恢复到某个检查点用 git

Claude Code 的检查点很方便，但它不是版本控制：通过 Bash 命令（rm、mv、cp）改动的文件，以及会话之外的修改，都不会被恢复。所以还是要常提交。详见 checkpointing 文档和 Codex 的斜杠命令。

难在哪里

  • 会话一多。每个 Agent 的 /diff 都在它自己的 pane 里。四个会话、四个 worktree，就要在四个地方分别 review，还得记住上次看完之后哪些又跑完了。
  • 会话结束之后。关掉会话或者开始下一个任务之后，想知道「第 3 轮改了什么」就只能去翻 git 历史，前提是你中间提交过。
  • 文档。Agent 写的设计文档、README 和 Mermaid 图越来越多。Markdown 的原始 diff 很难读，你想看的是排版后的文档，并标出改了哪几段。
  • 顺手改一下。Agent 有一行写错了，改它通常要打开编辑器，而这个文件 Agent 可能还在改。

gilvt 怎么做

gilvt 是一个 macOS 终端，它跟踪在其中运行的 Claude Code 和 Codex 会话。每一轮开始和结束时，它都会把工作区快照保存到自己的目录里（不碰 .git、暂存区和你的提交），所以每一轮的改动都一直能看，包括还没被跟踪的新文件。

  • 过程时间线（⌥⌘1）：每一轮的命令、编辑和失败；失败的命令直接显示关键报错行。点一行，终端滚回那里；⌘-点击文件名直接打开。
  • 产物（⌥⌘2）：每个任务一张卡片，列出改过的文件和 +a −b。打开文件可以看这一轮、这个任务或整个会话的 diff，行数和卡片上一致。
  • Quick Look：语法高亮的词级 diff，统一视图或左右对照，n / p 在改动块之间跳转。Markdown 直接显示排版后的效果，并标出新增和修改的段落；Mermaid 图离线渲染。
  • 在 shell 里：gilvt diff 逐个查看相对 HEAD 改过的文件（gilvt diff main 对比分支），gilvt view file:42 打开单个文件，⌘P 在仓库里找任意文件。
  • 就地修改：在预览里按 E，在终端旁边打开内置编辑器。如果你编辑时 Agent 也改了这个文件，gilvt 会显示「重新载入 / 对比 / 仍然覆盖」的提示条，不会悄悄覆盖任何一方。
  • 待 Review（⇧⌘R → ⌘2）：所有会话跑完的轮次进同一个队列，失败的排在前面。不用重新启动 Agent，就能看到提示词、Agent 的最终回答和工具调用，看完标记为已 review。

什么时候还是要打开 IDE

gilvt 负责阅读和小改动，它不是 IDE：编辑器没有代码补全和跳转定义，也还没有查找替换，Quick Look 里的文字暂时不能选中。要大改时，⌘⌥O 在外部编辑器里打开当前行（装了 code 命令时用 VS Code）。每轮快照和「产物」页只在你 Mac 上的 git 仓库里生效；SSH 远端的会话，在远端 shell 里用 gilvt diff。

试试看：下载 gilvt（免费，macOS 11 及以上），在一个 git 仓库里运行 claude 或 codex，第一轮结束后按 ⌥⌘2。
