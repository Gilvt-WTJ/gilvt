# V7 内置编辑器：编码菜单、只读与混合换行符
requires: sandbox
checklist: V7
scenarios: [default]

状态栏的编码一段可以点：弹出编码菜单（UTF-8、UTF-8（带 BOM）、UTF-16 LE / BE、GBK、Shift_JIS、EUC-KR、Big5、windows-1252、gb18030，
分隔线后「以只读方式打开」），选一个就用它重新读取文件；有未保存修改时先出确认条「重新打开会放弃未保存的改动。」（取消 / 放弃改动并重新打开）。
文件里同时有 LF 和 CRLF 时换行符一段是琥珀色「LF · 混合」，点它选 CRLF → 缓冲区变成未保存、闪「保存时使用 CRLF」，`⌘S` 后磁盘全是 CRLF。
只读缓冲区上点换行符一段不弹菜单。旧编码无法原样写回的文件（Shift_JIS 里的 NEC 扩展字符）被拒绝：不开 pane，窗口顶部红色横幅多出
「选择编码打开…」「以只读方式打开」。

样本（与 `gilvt-editor` 的 E1 测试同源，已用 `gilvt_editor::decode` 实测）：
- `gbk-note`：ASCII 头 + GBK 的「你好」（`C4 E3 BA C3`）。字节太少，自动检测**猜错**（今天是 EUC-KR，显示成乱码「콱봤」）；
  用例只断言「不是 GBK」，再从菜单选 GBK。
- `sjis-nec`：Shift_JIS 日文（`iconv` 生成）中间夹 NEC 扩展 `ED 40`（解码成「纊」，编码回去是 `FA 5C`）：chardetng 猜 Shift_JIS，
  往返不一致 → `UnsupportedEncoding`，被拒绝。
- `mixed-eol`：头 4 行 LF，正文 `a\r\nb\nc\r\n`（LF 多，所以是「LF · 混合」）。
- `locked`：`chmod a-w` 的普通文件 → 只读缓冲区（沙盒不以 root 运行；是 root 时 `test ! -w` 那一步失败，说明这部分不可信）。

默认字号（13）下「编辑」开新文件标签（见 V2），编辑 pane 在 `tabs[1]`。

**没有自动化的部分**（`debug state` 没有窗口级「不能编辑」红色横幅：既没有它的文字，也没有它的按钮的 rect）：
- 被拒绝文件横幅上的「以只读方式打开」「选择编码打开…」只能用鼠标点。用例只断言没有开出编辑 pane，并截图 `v7-refused` 看横幅和按钮；
  点按钮之后的结果（只读 pane、头部「只读 · 部分字符已替换」、`readonly == true`、`lossy == true`）写在步骤末尾的 `# 手动：` 注释里，
  无人值守（`run.sh`）时不检查，由用户手动确认。

- `v7-confirm`：头部下面横条「重新打开会放弃未保存的改动。」，按钮「取消」「放弃改动并重新打开」，后者是默认样式；头部显示 ●。
- `v7-mixed`：状态栏换行符一段是琥珀色「LF · 混合」（与其他段颜色不同）；正文 4 行 `---` 头，后面 `a`、`b`、`c` 各一行，行尾没有可见的 `\r` 或怪字符。
- `v7-refused`：标签栏下方红色横幅「不能编辑 SKILL.md：无法识别这个文件的编码」，右侧按钮「在外部编辑器中打开」「选择编码打开…」

- 没有自动化：被拒绝横幅上的按钮（见说明与步骤末尾的 `# 手动：`）；换行符段的悬停提示「文件里同时有多种换行符；保存会统一成 LF。」
