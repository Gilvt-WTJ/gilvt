如何通过 SSH 运行 Claude Code 和 Codex

把 Agent 放在代码旁边——开发机、GPU 服务器或构建机上——往往比把一切同步到笔记本更快，也更安全。难的不是启动它，而是及时发现某个远端会话停下来在等你。

发布于 2026-10-18 · 阅读约 6 分钟

简单说：在远端装好并登录 claude 或 codex，在项目目录里通过 SSH 启动它；事先想清楚断线时要保住的是进程（用 tmux）还是对话（用 claude --resume、codex resume）；最后让远端 Agent 的状态在本机可见，不必挨个翻 SSH 标签页。

为什么把 Agent 放在远端跑

  • 代码和环境都在那里。只有服务器上才有的构建、测试、数据库和 GPU，Agent 的工具可以直接用。
  • 隔离。会执行命令的 Agent 在一台可以随时重建的开发机上动手，而不是在你的笔记本上。
  • 长任务。跑二十分钟的测试不会占着你的电脑。

Mac 负责阅读、判断和审批，服务器负责干活。

1. 在远端安装并登录

Claude Code 和 Codex CLI 都支持 Linux 与 macOS。按各自文档在远端安装，然后在 SSH 会话里运行一次完成登录；无界面的服务器上，登录流程会给出一个链接，在本机浏览器里打开即可。每台主机、每个用户只需做一次，之后的会话沿用已保存的凭据。

ssh devbox
cd ~/src/payments-api
claude          # 或者：codex

要在项目目录里启动：两个 CLI 都按启动目录区分会话历史和项目设置。

2. 想清楚断线时要保住什么

SSH 断开时，这次登录里的进程通常会跟着结束，包括正在执行一轮任务的 Agent。恢复有两种方式，解决的问题不同：

远端 tmuxAgent resume
保住什么运行中的进程：断线期间 Agent 继续工作对话：历史、上下文和会话本身
怎么回去ssh devbox 后 tmux attachclaude --resume 或 claude --continue；codex resume
代价你和 Agent 界面之间多一层；鼠标、回滚和按键都要经过 tmux被打断的那一轮要重新提一次

网络稳定、交互较多的短会话，resume 通常就够了；长时间自主执行的任务或网络不稳时，把 Agent 放进 tmux。

3. 让重新连接足够便宜

如果同一台主机要开好几个 pane，让它们共用一条 SSH 连接，新 pane 秒开，也只需认证一次：

# ~/.ssh/config
Host devbox
  HostName devbox.example.com
  ControlMaster auto
  ControlPath ~/.ssh/cm-%r@%h:%p
  ControlPersist 10m
  ServerAliveInterval 30

ServerAliveInterval 还能让断掉的连接尽快报错，而不是一直卡住。

4. 别把远端会话跟丢

远端 Agent 真正的成本是注意力。本地 Agent 至少还能响一声；远端的那个停在某个 SSH 标签页里等审批，要等你碰巧切过去才知道。两三台主机、每台几个会话时，逐个检查标签页就成了主要工作。

有用的是在 Mac 上拿到和本地一样的信号——等待审批、在问你、出错、完成——并且能一步跳到那个 pane。用 Agent 的 hook 往回发消息可以做到一部分（见Claude Code 需要你时如何收到通知），但 hook 在服务器上执行，需要一条通回你 Mac 的路。

gilvt 怎么处理 SSH

在 gilvt 里照常输入 ssh。交互式登录到 Linux（x86_64 或 aarch64）或 Apple 芯片的 Mac 时，gilvt 会把这个 pane 当作远端：pane 和标签显示主机名，远端 shell 加载 gilvt 的 shell 集成，远端目录也会被跟踪。ssh host command、scp、git push 照常执行，不受影响。

  1. 第一次连某台主机时，gilvt 会问要不要在那里装一个小助手（~/.gilvt-server）。Y 安装，n 这次跳过，N 这台主机以后不再问。不装的话，ssh 就按原样登录。
  2. 在远端 shell 里照常运行 claude 或 codex。会话出现在 gilvt 左栏，和本地会话放在一起：同样的状态、系统通知、⇧⌘J 跳到待审批，以及按轮次的检查器时间线。
  3. 直接看远端文件：在远端 shell 里用 gilvt view、gilvt diff，或 ⌘-点击路径，在 Quick Look 里打开远端的文件；内置编辑器保存时写回远端。
  4. 以后再恢复：远端会话也在会话历史里（⇧⌘R），连接断了之后仍然可以恢复。

某次连接不想让 gilvt 处理，就用 command ssh host 或 GILVT_SSH=0 ssh host。从主机上移除助手：pkill -f '[.]gilvt-server/'; rm -rf ~/.gilvt-server。

目前的限制

gilvt 的 SSH 支持还是预览版，下面这些暂时做不到：

  • 远端 tmux 里的 Agent暂时识别不到。如果为了保活必须用 tmux，tmux 的好处还在，但这些会话不会出现在左栏。
  • 不支持 Intel Mac 作为远端、mosh，以及从远端再跳到第三台机器；这些连接按原样登录。
  • 远端 pane 暂时没有 ⌘P 找文件、git 状态，以及检查器的「产物」「配置」页。

完整列表见产品手册的 SSH 一节。
