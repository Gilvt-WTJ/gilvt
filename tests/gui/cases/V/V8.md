# V8 内置编辑器：语法高亮（Rust、Markdown、TOML、纯文本、大文件）
requires: sandbox
checklist: V8
scenarios: []

编辑 pane 按文件类型给文字着色：关键字 / 字符串 / 注释 / 数字 / 标题 / 键都着色，随主题切换；Markdown 开头的 YAML 头按 YAML 着色；
纯文本不着色（状态栏「纯文本」），大文件（> 2 MiB 或 > 50 000 行）不着色，状态栏写「（未高亮）」；在 Rust 文件开头输入 `/*` 后下面所有行变成注释色（增量失效），删掉后恢复。

**打开方式**：本用例不启动 Agent，所以不走配置标签的「编辑」，而是 `⌘P` 文件面板：沙盒里的终端 pane 在 `work/v8`（带 `.git` 目录）里，
面板搜这个目录的文件；输入文件名、`Enter` 打开 Quick Look 预览（`overlay.kind == "quicklook"`）、按 `e` 开编辑（默认字号下是新文件标签，
见 V2）。每个文件检查完用 `⌘⇧W` 关掉文件标签（未改动文件没有确认条）回到终端标签，再开下一个。
`work/v8` 里的 5 个文件（`hl-demo.md`、`conf.toml`、`notes.txt`、`big.rs`、`main.rs`）都在仓库根目录，没有被 `.gitignore` 排除。

**状态断言与截图的分工**：
- 状态里只有计数：`editors[0].highlight.visible_classes.<类别>` 是**最近一次绘制的可见行**里每个类别的连续区间数（按显示行数；
  没有的类别键不存在），所以断言只能证明「这个类别被着色了」，不能证明颜色好看、可读、各不相同——那是截图和 `## judge` 的事。
- Markdown：syntect 自带的 Markdown 语法**不嵌入其他语言**，围栏代码块整体是一个 `code` 区间；所以断言 `heading` 和 `code` 存在，
  **不**断言围栏里的 Rust 按 Rust 着色（也不会有 `keyword`）。
- Markdown 的 YAML 头（`hl-demo.md` 开头的 `---` … `---`）：头里的 `name`、`description` 是 `key`；两条 `---` 分隔行不着色，
  结尾的 `---` 也不会被当成 setext 标题下划线，所以整屏只有 `# Heading` 一个标题区间：断言 `key exists` 且 `heading == 1`。
- Rust 的 `i32` 等原始类型按 `keyword` 着色，不断言 `type`。
- 增量失效：`main.rs` 只有一行 `//` 注释，所以初始 `comment == 1`；文首输入 `/*` 后，整屏都在块注释里：`comment` 不再是 1、
  并且 `keyword` 不存在（DSL 没有 `>`，用 `!= 1` 加 `!exists`）；退格两次后回到 `comment == 1` 且 `keyword` 又出现。
  这个文件改过，所以关标签时有确认条（编辑历史没回到保存点，`dirty` 仍为 true）。
- 主题：沙盒默认 `theme = "light"`（`sandbox.sh`），默认截图是浅色；最后 `restart --set 'theme="dark"'` 再截一张深色，结束时改回 `light`。
- 状态栏文字（「Rust」「（未高亮）」）不在 `debug state` 里：`language`、`enabled`、`disabled_reason` 是它的来源，状态栏本身看截图。

## judge
- `v8-rust`（浅色，沙盒默认）：`fn`、`let` 等关键字，字符串 `"gilvt"`，注释 `// one comment line`，数字 `42`、`1`…各是一种颜色，**四种互不相同**，
  在白底上都清晰可读；普通标识符是正文色；状态栏语言是「Rust」，没有「（未高亮）」；当前行底色、光标仍正常。
- `v8-rust-comment`：文首 `/*` 之后，整屏文字都是注释色（和 `v8-rust` 里 `// one comment line` 同一个颜色），没有关键字色；
  光标和当前行底色仍正常。
- `v8-rust-dark`：同一个文件在深色主题下，四种颜色仍各不相同、深底上清晰可读；颜色与浅色版不同（随主题切换），不刺眼。
- `v8-markdown`：状态栏语言「Markdown」；YAML 头里的 `name`、`description` 是键色（不加粗），后面的值是字符串色；两条 `---` 分隔行是正文色
  （不是标题色、不加粗）；`# Heading` 一行是标题色（加粗，与正文不同）；`` `inline` `` 与下面围栏里的代码（`fn main() …`）
  是同一种「代码」色。**不要求**围栏里的 Rust 按 Rust 着色：syntect 自带的 Markdown 语法不嵌入其他语言，围栏整体是一个代码区间。
- `v8-toml`：状态栏「TOML」；`[server]` 是标题（加粗）；`name`、`port`、`debug` 是键色，`"gilvt"` 字符串色，`8080` 数字色，`true` 常量色，
  都着了色、清晰可读。**不要求**数字与常量不同色（两者共用一种颜色），也不要求键与标题不同色
  （同色相，标题靠加粗区分）。
- `v8-big`：状态栏写「Rust（未高亮）」之类（语言名 + 「（未高亮）」）；文字全是正文色，没有任何着色；编辑照常可用（滚动不卡）。
- 纯文本（`notes.txt`，只有断言）：状态栏写「纯文本」（不带「（未高亮）」，那是大文件的标记）；没有截图，需要时人工打开一次确认全是正文色。
- 选区、当前行底色、光标在所有截图里都正常，没有被语法色盖住。
- 结束时磁盘文件与最初完全一致（`diff -r` 步骤已覆盖）；最后的 `restart --set 'theme="light"'` 把主题改回沙盒默认；它失败时后面的用例都不可信，先停下来报告。
