# R13 真实 Claude：总结一次 + 对话一轮（带一次 MCP 调用），不留会话记录
requires: real-claude
checklist: R13
scenarios: []

验证真实 `claude` 的一次性总结、stream-json 多轮与 MCP 协议没有变化。前提（清单 Z 节）：真实 `~/.config/gilvt/config.toml` 的 `[monitor]` 已由用户本人设为 `enabled = true`、`provider = "claude"`（测试不修改它）。会产生费用。

## setup
```sh
# 录下对话进程的原始行（GILVT_MONITOR_RECORD，启动时读一次）；先清掉上一次的录制
rm -rf ~/gilvt-lab/r13/record && tests/gui/sandbox.sh real-up --label r13 --record ~/gilvt-lab/r13/record
```

## steps
```gilvt-steps
# 真实 gilvt 里 sh 被拒绝：标记文件与泄漏检查都在真实 shell 里做。不动检查器（会写真实 ui.json）：窄时面板是浮层
key    cmd+t
wait   windows[0].tabs[*].panes[?focused==true].foreground == "shell" timeout=15s
type   "mkdir -p ~/gilvt-lab/r13 && touch ~/gilvt-lab/r13/start.marker && cd -P ~/gilvt-lab/r13 && clear && echo r13-output && false\n"
wait   windows[0].tabs[*].panes[?focused==true].commands[0].exit == 1 timeout=10s
key    cmd+shift+o
wait   windows[0].monitor.cards[?meta_line contains "r13-output"].summary exists timeout=10s
click  'rect(windows[0].monitor.cards[?meta_line contains "r13-output"])'
key    s
wait   windows[0].monitor.cards[?meta_line contains "r13-output"].summary.state == "ready" timeout=120s
# a 问它：卡片已选中，打开面板（窄时是浮层）
key    a
wait   windows[0].monitor.chat.input.chips[*].key contains "pane:" && windows[0].monitor.chat.quick[?label=="哪些需要我？"].rect != null timeout=5s
click  'rect(windows[0].monitor.chat.quick[?label=="哪些需要我？"])'
wait   windows[0].monitor.chat.messages[?role=="assistant"].tools[?name=="list_sessions"].done == true timeout=120s
wait   windows[0].monitor.chat.status == "idle" timeout=180s
assert windows[0].monitor.chat.messages[?role=="assistant"].tools[?name=="list_sessions"].ok == true
assert chat_process.running == true && chat_process.provider == "claude"
shot   r13
# 「停止」：回答中点它，5 秒内回到空闲（真实 CLI 接受了中断），不是等中断超时后杀进程
click  'rect(windows[0].monitor.chat.input)'
type   "Please read the timeline of every session and explain each one in detail."
key    enter
wait   windows[0].monitor.chat.status == "answering" && windows[0].monitor.chat.stop != null timeout=60s
click  'rect(windows[0].monitor.chat.stop)'
wait   windows[0].monitor.chat.status == "idle" timeout=5s
assert windows[0].monitor.chat.messages[?text contains "中断没有响应"] !exists
assert chat_process.running == true && chat_process.provider == "claude"
shot   r13-stopped
# 窄时面板是盖在卡片墙上的浮层，会挡住「跳过去」：先收起
click  'rect(windows[0].monitor.chat.collapse)'
wait   windows[0].monitor.chat.open == false && windows[0].monitor.chat.rail != null timeout=5s
# 回到那个终端（卡片的「跳过去」），在里面做泄漏检查；命令记录最新在前
click  'rect(windows[0].monitor.cards[?meta_line contains "r13-output"].jump)'
wait   windows[0].tabs[*].panes[?focused==true].cwd contains "/gilvt-lab/r13" timeout=5s
type   "test -z \"$(find ~/.claude/projects -newer ~/gilvt-lab/r13/start.marker -name '*.jsonl' -path '*gilvt-state-monitor-run*')\"\n"
wait   windows[0].tabs[*].panes[?focused==true].commands[0].exit == 0 timeout=15s
# 录到的 system/init：工具恰好是 gilvt 的五个（排序后拼接比较；. 代替引号，\012 是换行，\042 是引号）
type   "test \"$(grep -h 'subtype.:.init' ~/gilvt-lab/r13/record/claude-*.jsonl | head -n 1 | sed -e 's/.*[{,].tools.:\[//' -e 's/\].*//' | tr , '\012' | sort | tr -d '\042\012 ')\" = mcp__gilvt__get_commandsmcp__gilvt__get_sessionmcp__gilvt__get_timelinemcp__gilvt__list_sessionsmcp__gilvt__read_screen\n"
wait   windows[0].tabs[*].panes[?focused==true].commands[0].exit == 0 timeout=15s
# chat.log 与录制里没有 token：既没有变量名，也没有 32 个十六进制字符的值
type   "! grep -qE 'GILVT_MONITOR_TOKEN|(^|[^0-9a-f])[0-9a-f]{32}([^0-9a-f]|\$)' ~/'Library/Application Support/gilvt/state/monitor/chat.log' ~/gilvt-lab/r13/record/claude-*.jsonl\n"
wait   windows[0].tabs[*].panes[?focused==true].commands[0].exit == 0 timeout=15s
```

## teardown
```sh
tests/gui/sandbox.sh down --keep ~/gilvt-lab/reports/<日期>-<标签>/R13
```

## judge
- 没有用 `sh`（real-up 里被拒绝）；泄漏检查是最后一行在真实 shell 里键入的命令，`exit == 0` 即没有新记录。
- 终端卡片的 ✦ 块有「近期：…」，内容与 `false` 失败相符。
- `r13`：面板（宽时是侧栏，窄时是浮层）里回答上方是「✓ 已列出 N 个会话」，回答说明了哪些会话需要用户（或说明没有）；没有声称执行过任何操作。
- `~/.claude/projects` 下没有名字含 `gilvt-state-monitor-run` 的新会话记录（`--no-session-persistence` 生效）。
- `r13-stopped`：第二个问题的回答被「停止」中断，下面是「（这一轮已中断）」（若回答在点击前已经结束，则是完整回答；记进报告），没有「中断没有响应，已结束监控官进程」，进程没有重启。
- 录制（`real-up --record`）的 `system/init` 里 `tools` 恰好是 `mcp__gilvt__{get_commands,get_session,get_timeline,list_sessions,read_screen}` 五个；`chat.log` 与录制文件里没有 `GILVT_MONITOR_TOKEN`，也没有 32 个十六进制字符的值（两条都是真实 shell 里键入的命令，`exit == 0` 即通过）。
- 报告里记下 `claude --version`，附上录制文件路径（`~/gilvt-lab/r13/record/claude-<pid>.jsonl`）。
