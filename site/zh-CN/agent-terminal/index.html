Agent 终端

什么是 AI Agent 终端？

Agent 终端首先是一个真正的终端，同时理解编程 Agent 的生命周期：哪个会话正在执行、被阻塞、询问问题、等待审批或已经完成。

发布于 2026-10-08 · 阅读约 6 分钟

简短回答：普通终端显示文本；Agent 终端在此之上理解 Claude Code、Codex 等会话的结构化状态，同时让 Agent 保留原生的命令行界面。

为什么普通终端难以管理编程 Agent

传统终端适合一个人控制一个前台命令。编程 Agent 改变了这种关系：开发者会启动多个会话，转去处理其他任务，只有 Agent 需要审批、提问或完成一轮时才回来。

在普通标签页和分屏里，每个会话都只是一块文字。你必须逐个打开才能回答：

  • Agent 还在执行，还是十分钟前已经停了？
  • 哪个会话正在等待审批或回答？
  • 上一轮修改了哪些文件？
  • 几天前的会话能否安全恢复？

此时瓶颈已经不是终端渲染，而是如何管理多个异步工作者对人的注意力需求。

层面普通终端Agent 终端

gilvt 如何观察 Agent

gilvt 不会用自有聊天界面替换 Claude Code 或 Codex。Agent 继续运行在自己的 TUI 中。gilvt 把 shell integration、Agent hooks、会话记录和进程信息合并成统一状态。

这些状态驱动左栏、pane 描边、系统通知、逐轮时间线和产物 review。某项集成不可用时，终端仍然正常工作，会话只会退回能力较少的模式。

Agent 终端不等于自动化编排器

编排器通常拥有 prompt、审批和任务执行图。Agent 终端可以采取更克制的方式：只观察、组织和导航，不代替用户回答。

gilvt 采用后一种模型。它不会替你输入或批准命令，你保留原来的 CLI 行为与配置，只增加一个管理多会话的工作空间。

它与 tmux 的关系

tmux 解决的是另一个问题：让终端进程由后台 server 持有，从而 detach 和重新连接。Agent 终端关注原生 UI 和 Agent 语义。远程工作时，可以用 tmux 保持服务器进程，用 gilvt 提供本地 macOS 界面。

更完整的进程和会话生命周期差异见 gilvt 与 tmux 对比。

试用：下载 macOS 版 gilvt，打开一个 pane，运行 claude 或 codex，会话会自动出现在左栏。
