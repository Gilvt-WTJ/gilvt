# H22 往下滚着看旧事件时，新事件不顶走视野
requires: sandbox
checklist: H22
scenarios: [timeline-live]

用户把检查器往下滚去看较早的事件，这时又有新事件加到最上面：正在看的那一行不能动（位置不变），不能被自动拉回顶部或底部。
再往上滚回顶部，能看到最新的几条。含滚动（前台动作）。

## steps
```gilvt-steps
wait   windows[0].tabs[0].panes[0].foreground == "shell" && windows[0].tabs[0].panes[0].screen_tail[*] contains "sandbox$" timeout=15s
type   "mkdir -p ~/work/h22 && cd -P ~/work/h22 && clear\n"
wait   windows[0].tabs[0].panes[0].cwd contains "/work/h22"
type   "claude @scenario:timeline-live\n"
wait   windows[0].inspector.rows[?label=="Bash echo step 41"] exists timeout=30s
scroll down 6 'rect(windows[0].inspector.rows[2])'
wait   windows[0].inspector.rows[?label=="Bash echo step 12"].rect != null timeout=5s
# 记下 step 12 此刻的 rect（下面两次 state 的 y 必须相同）
state  windows[0].inspector.rows[?label=="Bash echo step 12"].rect
wait   windows[0].inspector.rows[?label=="Bash echo step 50"] exists timeout=30s
state  windows[0].inspector.rows[?label=="Bash echo step 12"].rect
assert windows[0].inspector.rows[?label=="Bash echo step 12"].rect != null
assert windows[0].inspector.rows[1].rect == null
shot   h22-scrolled
scroll up 40 'rect(windows[0].inspector.rows[?label=="Bash echo step 12"])'
wait   windows[0].inspector.rows[1].rect != null timeout=5s
shot   h22-top
```

## judge
- 两次 `state` 打印的 `step 12` 的 rect 完全相同（y 一样）：期间新增了 `step 42`…`step 50` 共 9 行，视野没有被推走。
- `h22-scrolled`：检查器显示的是较早的事件（`step 12` 附近），顶部看不到最新的几条。
- `h22-top`：往上滚到顶后，最上面是 `step 52`、`step 51`……
