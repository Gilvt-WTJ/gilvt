Claude Code 需要你时如何收到通知

Claude Code 经常停下来请你批准执行一条命令，而这时你多半在浏览器里。下面是在 macOS 上第一时间知道的几种办法，从改一个设置到写 hook，以及它们各自的局限。

发布于 2026-10-18 · 阅读约 6 分钟

简单说：在 Terminal.app 等大多数终端里，Claude Code 默认不弹桌面通知。可以在 /config 里把 Local notifications 改成终端响铃，或者加一个 Notification hook（审批、等待输入）和一个 Stop hook（一轮完成）来发 macOS 通知。Codex 用 [tui] notifications 或 notify 程序。会话一多，你还需要知道是哪一个在等你，并能一步过去。

哪些事值得通知

不是每个事件都值得打断你。实际用下来，你在别的应用里时值得知道的有四种：

  • 等待审批或在问你——会话卡在你这里，应该马上通知。
  • 出错——API 错误或一轮失败。要通知，但不必响。
  • 耗时较长的一轮完成了——十分钟的重构值得提醒，五秒的回答只是噪音。
  • 上下文快满了——提醒一次就够。

办法一：Claude Code 的内置设置

Claude Code 只在 iTerm2、Ghostty、Kitty 里会自己弹桌面通知。其他终端里，在 Claude Code 中打开 /config，修改 Local notifications（对应设置项 preferredNotifChannel）。terminal_bell 会让终端响铃，大多数终端会把它变成提示音或 Dock 图标跳动。写在 ~/.claude/settings.json 里是这样：

{
  "preferredNotifChannel": "terminal_bell"
}

其他取值有 auto（默认）、iterm2、iterm2_with_bell、kitty、ghostty 和 notifications_disabled。响铃只能告诉你「有事」，说不清是什么事、在哪个会话。

办法二：用 hook 发 macOS 通知

Claude Code 会在特定事件上执行 hook，这里用到两个：

  • Notification：权限请求等了大约 6 秒、Claude 回答完大约一分钟你还没输入，以及其他几种提示时触发。即使关掉桌面通知它也会触发。
  • Stop：Claude 回答完时触发（你主动打断时不触发）。

写在 ~/.claude/settings.json 里，对所有项目生效：

{
  "hooks": {
    "Notification": [
      { "hooks": [ { "type": "command",
        "command": "osascript -e 'display notification \"Claude Code 在等你\" with title \"Claude Code\" sound name \"Glass\"'" } ] }
    ],
    "Stop": [
      { "hooks": [ { "type": "command",
        "command": "osascript -e 'display notification \"Claude Code 完成了\" with title \"Claude Code\"'" } ] }
    ]
  }
}

matcher 字段可以不写：Notification 不写就匹配所有通知类型，Stop 会忽略它。hook 还会从标准输入收到这次事件的 JSON，写个小脚本就能把项目目录或通知类型放进消息里。

Codex

Codex CLI 在 ~/.codex/config.toml 里有对应的配置。它的 TUI 自己就能通知你，审批请求也包括在内：

# ~/.codex/config.toml
notify = ["python3", "/Users/you/.codex/notify.py"]   # 顶层键要写在所有 [表] 之前

[tui]
notifications = ["agent-turn-complete", "approval-requested"]

notify 指定的程序在一轮完成时执行（目前只有这一种事件），收到一个 JSON 参数，包含 type、cwd、last-assistant-message 等字段。细节见 Codex 配置文档。

自己配的通知，局限在哪里

只有一个会话时，一个 hook 就够了。开到四个时，同一条通知会来四次，新的问题也随之出现：

  • 是哪个会话？「Claude Code 在等你」说不出是哪个标签页、哪个项目、哪个任务。
  • 点了也过不去。osascript 发的通知属于「脚本编辑器」，点击它不会带你到正在等待的终端 pane。
  • 没有总数。回来之后还是得翻遍标签页，才知道有几个卡住了。
  • 远端会话。SSH 主机上会话的 hook 在那台主机上执行，osascript 够不到你的 Mac。
  • 噪音。没有按会话静音、没有最短耗时门槛，「完成」通知很快就会被你无视。

gilvt 怎么做

gilvt 是一个 macOS 终端，它跟踪自己运行的每个 Claude Code、Codex 会话的状态，所以通知能带上 hook 拿不到的上下文。不需要任何配置：它在启动 Agent 时注入自己的 hook，不改 ~/.claude 和 ~/.codex。

状态何时通知声音
等待审批 / 在问你立即有
出错立即无
一轮完成这一轮用时 30 秒以上时无
上下文用到 90%每个会话一次无
  • 每条通知都写明 Agent、项目和会话名，以及它在等什么；只在 gilvt 不在前台或那个 pane 不可见时才发。点击通知直接跳到那个 pane，光标就在 Agent 的输入框里。
  • Dock 角标显示在等你的会话数；有会话开始等你时 Dock 图标跳一下（[notify] dock_bounce = false 可关闭）。
  • 回到 gilvt，这些会话排在左栏最上面；⇧⌘J 跳到等得最久的那个。
  • 在左栏右键某个会话可以静音。
  • SSH 主机上的会话也同样会通知。

第一次有会话需要你时，macOS 会询问是否允许 gilvt 发通知，选「允许」即可；之后可以在「系统设置 → 通知 → gilvt」里修改。
