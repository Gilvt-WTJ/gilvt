# H6 同步子 Agent 的嵌套显示
requires: real-claude
checklist: H6
scenarios: []

fake agent 不产生子 Agent 的 sidechain 记录，所以用真实 claude。Task / Agent 行为紫色，下方用紫色竖线嵌套子 Agent 自己的事件，
末尾是灰色「↩ <子 Agent 结果首句>」。顺带检查 H5 里「子 Agent 内命中过滤的事件连同其 Task 行一起显示」。

## setup
```sh
tests/gui/sandbox.sh real-up --label h6
```

## steps
```gilvt-steps
wait   windows[0].tabs[0].panes[0].foreground == "shell" timeout=15s
type   "mkdir -p ~/gilvt-lab/h6 && cd -P ~/gilvt-lab/h6 && clear\n"
wait   windows[0].tabs[0].panes[0].cwd contains "/gilvt-lab/h6"
type   "claude --no-chrome\n"
wait   windows[0].tabs[0].panes[0].foreground == "agent:claude" timeout=30s
# 在这个目录第一次运行时 Claude 会先问是否信任它：screen_tail 里出现 trust 字样时执行 key enter
type   "用 Task 工具派生一个 general-purpose 子 Agent，让它用 Bash 执行 ls 并用一句话汇报结果；同步等它返回后，再用一句话回复我。不要用后台任务。\n"
wait   windows[0].inspector.card.status != "idle" timeout=30s
# 子 Agent 的 Bash 可能要审批：出现 awaiting_approval 时执行 key enter（选 Yes）
wait   windows[0].inspector.card.status == "idle" timeout=240s
shot   h6-subagent
assert windows[0].inspector.rows[?kind=="subagent"] exists && windows[0].inspector.rows[?nested==true] exists
click  'rect(windows[0].inspector.chips[?label=="Bash"])'
wait   windows[0].inspector.filter == "Bash" && windows[0].inspector.rows[?kind=="subagent"] exists timeout=3s
shot   h6-filter-bash
click  'rect(windows[0].inspector.chips[?label=="全部"])'
wait   windows[0].inspector.filter == "全部" timeout=3s
type   "/exit\n"
wait   windows[0].tabs[0].panes[0].foreground == "shell" timeout=15s
```

## teardown
```sh
tests/gui/sandbox.sh down --keep ~/gilvt-lab/reports/<日期>-<标签>/H6
```

## judge
- `h6-subagent`：Task（或 Agent）行为紫色；其下用紫色竖线嵌套子 Agent 的 `Bash ls` 等事件；嵌套块末尾有灰色
  「↩ <子 Agent 结果的第一句>」。
- `h6-filter-bash`：`ls` 仍然显示，并且连同它所属的紫色 Task 行一起显示。
- 如果 Claude 把任务放到了后台（异步子 Agent），这次不算数：`/exit` 后重跑并在提示词里强调同步等待。
- 这是真实 claude 用例：会产生费用，会话写入真实的 `~/.claude`；报告里记下 `claude --version`。
