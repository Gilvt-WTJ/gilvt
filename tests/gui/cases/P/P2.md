# P2 kill -9 之后恢复到最近 1–2 秒内的布局
requires: sandbox
checklist: P2
scenarios: []

布局每秒比较一次、有变化才写 `workspace.json`。应用被 `kill -9`（没有机会做退出时的同步保存）后重开，恢复的是最近一次定时写入的布局：
至少 2 秒前做的改动都在。

## steps
```gilvt-steps
wait   windows[0].tabs[0].panes[0].foreground == "shell" && windows[0].tabs[0].panes[0].screen_tail[*] contains "sandbox$" timeout=15s
type   "mkdir -p ~/work/p2/a ~/work/p2/b ~/work/p2/c && cd -P ~/work/p2/a && clear\n"
wait   windows[0].tabs[0].panes[0].cwd contains "/work/p2/a"
# 改动 A：左右分屏，右边 pane 在 b
key    cmd+d
wait   windows[0].tabs[0].panes[*] exists count=2 && windows[0].tabs[0].panes[1].focused == true && windows[0].tabs[0].panes[1].foreground == "shell" timeout=10s
type   "cd -P ~/work/p2/b && clear\n"
wait   windows[0].tabs[0].panes[1].cwd contains "/work/p2/b"
sleep  3s
# 改动 B：新标签，在 c
key    cmd+t
wait   windows[0].tabs[*] exists count=2 && windows[0].tabs[1].active == true && windows[0].tabs[1].panes[0].foreground == "shell" timeout=10s
type   "cd -P ~/work/p2/c && clear\n"
wait   windows[0].tabs[1].panes[0].cwd contains "/work/p2/c"
# 等两个定时周期，保证 B 已经写进文件；然后只给 gilvt 自己的进程（session.env 里记的 PID）发 SIGKILL
sleep  2500ms
state  windows[0].layout
sh     '. "${TMPDIR%/}/gilvt-gui-current/session.env" && kill -9 "$PID"'
sleep  1s
restart
wait   windows[0].layout.tabs[*] exists count=2 timeout=20s
assert windows[0].layout.tabs[0].tree.children[*].pane.cwd contains "/work/p2/a"
assert windows[0].layout.tabs[0].tree.children[*].pane.cwd contains "/work/p2/b"
assert windows[0].layout.tabs[1].tree.pane.cwd contains "/work/p2/c"
assert pending == []
wait   windows[0].tabs[0].panes[*] exists count=2 && windows[0].tabs[0].panes[0].cwd contains "/work/p2/a" && windows[0].tabs[0].panes[1].cwd contains "/work/p2/b" && windows[0].tabs[1].panes[0].cwd contains "/work/p2/c" timeout=15s
state  windows[0].layout
shot   p2-after
```

## judge
- 重开后的 `layout`（`p2-after` 之前的 `state`）与杀进程前的那一份（第一次 `state`）相同：分屏、两个标签、各 pane 的 cwd。
- 这条用例只验证「2 秒前的改动不丢」；杀进程前不到 1 秒内的改动可能没写进去，属于预期（没有断言）。
- 杀进程那一步用的是 `session.env` 里记的沙盒 gilvt 的 PID，不会碰到你自己的 gilvt；报告里应能看到 `sh` 步骤成功。
