# R14 真实 Codex：总结一次 + 对话一轮（带一次 MCP 调用），没有新的 rollout
requires: real-codex
checklist: R14
scenarios: []

验证真实 `codex` 的一次性总结、app-server 线程 / 轮次与 MCP 协议没有变化。前提（清单 Z 节）：真实 `~/.config/gilvt/config.toml` 的 `[monitor]` 已由用户本人设为 `enabled = true`、`provider = "codex"`（`command` 是用户本人设的，例如 `codex-w`；测试不修改它）。会产生费用。

## setup
```sh
# 录下对话进程的原始行（GILVT_MONITOR_RECORD，启动时读一次）；先清掉上一次的录制
rm -rf ~/gilvt-lab/r14/record && tests/gui/sandbox.sh real-up --label r14 --record ~/gilvt-lab/r14/record
```

## steps
```gilvt-steps
# 真实 gilvt 里 sh 被拒绝：标记文件与泄漏检查都在真实 shell 里做。不动检查器（会写真实 ui.json）：窄时面板是浮层
key    cmd+t
wait   windows[0].tabs[*].panes[?focused==true].foreground == "shell" timeout=15s
type   "mkdir -p ~/gilvt-lab/r14 && touch ~/gilvt-lab/r14/start.marker && cd -P ~/gilvt-lab/r14 && clear && echo r14-output && false\n"
wait   windows[0].tabs[*].panes[?focused==true].commands[0].exit == 1 timeout=10s
key    cmd+shift+o
wait   windows[0].monitor.cards[?meta_line contains "r14-output"].summary exists timeout=10s
click  'rect(windows[0].monitor.cards[?meta_line contains "r14-output"])'
key    s
wait   windows[0].monitor.cards[?meta_line contains "r14-output"].summary.state == "ready" timeout=120s
# a 问它：卡片已选中，打开面板（窄时是浮层）
key    a
wait   windows[0].monitor.chat.input.chips[*].key contains "pane:" && windows[0].monitor.chat.quick[?label=="哪些需要我？"].rect != null timeout=5s
click  'rect(windows[0].monitor.chat.quick[?label=="哪些需要我？"])'
wait   windows[0].monitor.chat.messages[?role=="assistant"].tools[?name=="list_sessions"].done == true timeout=120s
wait   windows[0].monitor.chat.status == "idle" timeout=180s
assert windows[0].monitor.chat.messages[?role=="assistant"].tools[?name=="list_sessions"].ok == true
assert chat_process.running == true && chat_process.provider == "codex"
shot   r14
# 「停止」：回答中点它，5 秒内回到空闲（真实 CLI 接受了中断），不是等中断超时后杀进程
click  'rect(windows[0].monitor.chat.input)'
type   "Please read the timeline of every session and explain each one in detail."
key    enter
wait   windows[0].monitor.chat.status == "answering" && windows[0].monitor.chat.stop != null timeout=60s
click  'rect(windows[0].monitor.chat.stop)'
wait   windows[0].monitor.chat.status == "idle" timeout=5s
assert windows[0].monitor.chat.messages[?text contains "中断没有响应"] !exists
assert chat_process.running == true && chat_process.provider == "codex"
shot   r14-stopped
# 窄时面板是盖在卡片墙上的浮层，会挡住「跳过去」：先收起
click  'rect(windows[0].monitor.chat.collapse)'
wait   windows[0].monitor.chat.open == false && windows[0].monitor.chat.rail != null timeout=5s
# 回到那个终端（卡片的「跳过去」），在里面做泄漏检查；命令记录最新在前
click  'rect(windows[0].monitor.cards[?meta_line contains "r14-output"].jump)'
wait   windows[0].tabs[*].panes[?focused==true].cwd contains "/gilvt-lab/r14" timeout=5s
type   "test -z \"$(find ~/.codex/sessions -newer ~/gilvt-lab/r14/start.marker -name 'rollout-*.jsonl' -exec grep -l '\"cwd\":\"[^\"]*gilvt/state/monitor/run' {} +)\"\n"
wait   windows[0].tabs[*].panes[?focused==true].commands[0].exit == 0 timeout=15s
# 录到的线程（app-server 不列出工具清单）：用过 gilvt 的工具，没有命令执行 / 文件改动条目，也没有 read_file、list_dir、grep_files、shell 工具（. 代替引号）
type   "grep -q '.server.:.gilvt.' ~/gilvt-lab/r14/record/codex-*.jsonl && ! grep -qE '.type.:.(commandExecution|fileChange).|.(tool|name).:.(read_file|list_dir|grep_files|shell|local_shell|shell_command).' ~/gilvt-lab/r14/record/codex-*.jsonl\n"
wait   windows[0].tabs[*].panes[?focused==true].commands[0].exit == 0 timeout=15s
# chat.log 与录制里没有 token：既没有变量名，也没有 32 个十六进制字符的值
type   "! grep -qE 'GILVT_MONITOR_TOKEN|(^|[^0-9a-f])[0-9a-f]{32}([^0-9a-f]|\$)' ~/'Library/Application Support/gilvt/state/monitor/chat.log' ~/gilvt-lab/r14/record/codex-*.jsonl\n"
wait   windows[0].tabs[*].panes[?focused==true].commands[0].exit == 0 timeout=15s
```

## teardown

tests/gui/sandbox.sh down --keep ~/gilvt-lab/reports/<日期>-<标签>/R14

## judge
- 没有用 `sh`（real-up 里被拒绝）；泄漏检查是最后一行在真实 shell 里键入的命令，`exit == 0` 即没有新记录。
- 终端卡片的 ✦ 块有「近期：…」，内容与 `false` 失败相符。
- `r14`：面板（宽时是侧栏，窄时是浮层）里回答上方是「✓ 已列出 N 个会话」，回答说明了哪些会话需要用户（或说明没有）；没有声称执行过任何操作。
- `~/.codex/sessions` 下没有新的、记录了监控官运行目录（`gilvt/state/monitor/run`）的 rollout（`thread/start` 的 `ephemeral: true` 与 `codex exec --ephemeral` 生效）。
- `r14-stopped`：第二个问题的回答被「停止」中断，下面是「（这一轮已中断）」（若回答在点击前已经结束，则是完整回答；记进报告），没有「中断没有响应，已结束监控官进程」，进程没有重启。
- 录制（`real-up --record`）里有 gilvt 的 `mcpToolCall`，没有 `commandExecution` / `fileChange` 条目，也没有名为 `read_file` / `list_dir` / `grep_files` / `shell` 的工具（app-server 协议不列出线程的工具清单，只能看实际出现的条目）；`chat.log` 与录制文件里没有 `GILVT_MONITOR_TOKEN`，也没有 32 个十六进制字符的值（两条都是真实 shell 里键入的命令，`exit == 0` 即通过）。
- 报告里记下 `codex --version`（或包装脚本的版本），附上录制文件路径（`~/gilvt-lab/r14/record/codex-<pid>.jsonl`）。
