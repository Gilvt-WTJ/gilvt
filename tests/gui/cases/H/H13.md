# H13 精简模式的时间线
requires: sandbox
checklist: H13
scenarios: [lite-mixed]

`lite-mixed` 不发任何 hook（等同 `claude --bare`）：时间线只来自会话记录，行都没有锚点；失败、已拒绝仍有颜色。

## steps
```gilvt-steps
wait   windows[0].tabs[0].panes[0].foreground == "shell" && windows[0].tabs[0].panes[0].screen_tail[*] contains "sandbox$" timeout=15s
type   "mkdir -p ~/work/h13 && cd -P ~/work/h13 && clear\n"
wait   windows[0].tabs[0].panes[0].cwd contains "/work/h13"
type   "claude @scenario:lite-mixed\n"
# 精简模式：第一条提示词写进会话记录后约 3 秒才出现这一行
wait   windows[0].sidebar.rows[?section=="project:h13"].lite == true timeout=15s
wait   windows[0].tabs[0].panes[0].screen_tail[*] == "⏺ Bash(rm -rf target)" timeout=10s
# 精简模式下审批不进「需要你」
assert windows[0].sidebar.rows[?section=="needs_you"] !exists
key    n
wait   windows[0].sidebar.rows[?section=="project:h13"].detail contains "sleep 30" timeout=15s
key    esc
wait   windows[0].sidebar.rows[?section=="project:h13"].status == "idle" timeout=15s
# git status / cargo build / rm -rf target 在第 1 轮：Esc 时的当前轮是第 2 轮，第 1 轮已折叠成历史轮次，先展开它
click  'rect(windows[0].inspector.rows[?kind=="history_turn"])'
wait   windows[0].inspector.rows[?kind=="history_turn"].expanded == true && windows[0].inspector.rows[?label contains "git status"].rect != null timeout=3s
shot   h13
assert windows[0].inspector.rows[?kind=="tool"] exists count=4 && windows[0].inspector.rows[?kind=="tool"].anchored != true
click  'rect(windows[0].inspector.rows[?label contains "git status"])'
wait   windows[0].inspector.rows[?label contains "git status"].expanded == true timeout=3s
assert windows[0].inspector.toast == null
shot   h13-clicked
```

## judge
- `h13`：展开的「第 1 轮」里是 `git status`、`cargo build`、`rm -rf target`，当前第 2 轮是 `sleep 30`。所有行都是灰色（没有锚点），但 `cargo build` 仍是红色 ✗ `exit 101`，`rm -rf target` 是黄色「⊘ 已拒绝」，
  `sleep 30` 也是黄色——精简模式下 Esc 中断的调用在会话记录里与拒绝相同，显示为「⊘ 已拒绝」（fake agent 的
  `lite_mixed_…` 测试钉住了这一点；有 hook 时同样的调用是「已中断」，见 H11）。
- `h13-clicked`：点击只就地展开详情，终端没有滚动、没有任何提示。
- 子 Agent 行为紫色这一项 fake agent 无法产生，由 H6 覆盖。
